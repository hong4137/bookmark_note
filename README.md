# 독서 노트 봇

책 페이지를 찍어 텔레그램으로 보내면 문장 단위로 파싱해 쌓고, 나중에 앱에서 원하는 문장만 골라 독서 노트로 남긴다.

> 왜 이렇게 만들었는지 · 데이터 구조 · 화면 흐름은 **[설계.md](설계.md)** 에 있다.

```
book-notes/
├── 설계.md          ← 먼저 읽을 것
├── README.md        ← 이 문서 (설치)
├── book-bot/        ← ① 텔레그램 봇 (완성)
│   ├── appsscript.json
│   ├── Code.gs
│   └── Setup.gs
└── book-app/        ← ② 하이라이트 앱 (아직)
```

현재 **①번 봇까지 만들어져 있다.** 봇을 먼저 돌려 시트에 실제 데이터가 쌓이는 걸 확인한 뒤 앱을 만드는 편이 낫다 — 실제 파싱 결과를 보고 화면을 잡아야 헛손질이 없다.

---

## 준비물 2개

명함봇과 달리 **Google Cloud도, OAuth 동의 화면도, 도메인도 필요 없다.** 전부 내 계정이라서.

### ① 텔레그램 봇 토큰 (새로 만들 것)

텔레그램 **@BotFather** → `/newbot` → 이름 정하기 → 토큰 복사

> 명함봇과 **다른 봇**이어야 한다. 봇 하나의 메시지 큐는 하나뿐이라, 두 스크립트가 같은 봇을 보면 서로 메시지를 뺏는다.

### ② Gemini API 키

<https://aistudio.google.com/apikey> → **API 키 만들기**

명함봇 키를 그대로 써도 되지만, 한도를 따로 보려면 새로 발급하는 편이 낫다.

## 설치

### 0단계 — 스크립트 만들기

<https://script.google.com> → **새 프로젝트** (이름: `book-bot`)

- ⚙️ **프로젝트 설정** → `appsscript.json` 매니페스트 파일 표시 **체크**
- `book-bot/` 의 파일 3개를 각각 붙여넣기 (`Setup.gs`는 ＋ → 스크립트로 새로 생성)

### 1단계 — `step1_설정값저장`

`Setup.gs` 맨 위 `SETUP` 두 칸에 준비물 ①②를 넣고 실행.

> 승인 창이 뜨면 내 계정으로 승인. 이번엔 **드라이브·스프레드시트 권한**도 함께 요구한다.
> 사진을 저장하고 시트를 만들어야 해서다.

### 2단계 — `step2_저장소_생성`

실행하면 내 드라이브에 이렇게 만들어진다.

```
내 드라이브/
└── 독서노트/
    ├── 원본사진/        ← 찍은 페이지 사진
    └── 독서 노트 (시트)  ← 탭 2개: 페이지 / 노트
```

로그에 뜬 시트 링크를 열어 탭 두 개와 헤더가 제대로 들어갔는지 확인.

### 3단계 — `step3_트리거_설치`

그냥 실행하면 됩니다. **배포할 필요가 없습니다.**

1분마다 텔레그램에 새 메시지가 있는지 확인하는 타이머가 걸립니다.

> **왜 웹훅이 아니라 폴링인가**
> Apps Script 웹앱은 `/exec` 요청에 항상 **302 리디렉션**을 돌려주는데, 텔레그램은
> 리디렉션을 따라가지 않고 실패로 간주합니다. 실패한 메시지를 재시도하는 동안
> 뒤에 온 메시지가 큐에 막혀 영영 전달되지 않습니다. 폴링에는 그 문제가 없습니다.
>
> 대신 **답장이 최대 1분까지 늦어집니다.** 급하면 `지금_확인` 을 실행하면 즉시 처리됩니다.
> 하루 실행시간이 부담되면 `POLL_MINUTES` 를 5로 올리세요.

### 4단계 — 내 텔레그램 등록

**`step4_등록코드_발급`** → 로그의 코드 복사 → 텔레그램에서 봇 열기 → **[시작]** → 코드 입력

> 이 단계 전까지 봇은 아무 메시지도 받지 않는다. 봇 주소를 모르면 `봇주소_확인` 실행.

### 5단계 — 써보기

```
/책 데미안
```

그 다음 책 페이지를 찍어 보내면 이런 답이 온다.

```
📖 데미안 87쪽 · 문장 6개

1. 그는 오래 침묵했다.
2. 새는 알에서 나오려고 투쟁한다.
...

⟩ 마지막 문장이 다음 페이지로 이어집니다
```

시트 `페이지` 탭에 행이 쌓이면 성공.

---

## 명령

| 입력 | 결과 |
|---|---|
| `/책 데미안` | 읽는 책 설정. 이후 사진은 전부 이 책으로 |
| `/책` | 지금 무슨 책인지 |
| `/앱` | 독서 노트 앱 열기 (앱 배포 후) |
| 📷 사진 | 파싱 → 저장 → 결과 답장 |

책은 **한 번만 정하면 된다.** 매 사진마다 캡션을 달 필요 없다.

---

## 잘 찍는 요령

파싱 정확도는 사진 품질이 거의 다 결정한다.

- **펼친 양면으로** 찍으면 문장이 페이지에서 잘리지 않아 제일 깔끔하다
- 페이지가 **평평하게** 펴지도록. 휘어진 부분에서 행이 겹치거나 늘어난다
- 그림자와 손가락이 글자를 가리지 않게
- 봇 답장을 **그 자리에서 눈으로 확인**하는 것이 1차 검증이다. 이상하면 바로 다시 찍는다

읽지 못한 글자는 `▯` 로 표시된다. 지어내지 않는다.

## 점검 · 문제 해결

| 증상 | 확인 |
|---|---|
| 봇이 무응답 | `상태확인` → 「수신 트리거」가 작동 중인지. 없으면 `step3_트리거_설치` |
| 답장이 느림 | 정상입니다(최대 1분). 즉시 처리하려면 `지금_확인` |
| "지정된 사용자만" | 4단계 미완. `step4_등록코드_발급` 후 코드 입력 |
| "먼저 책을 정해주세요" | `/책 책이름` 부터 |
| "시트 탭을 찾을 수 없습니다" | `step2_저장소_생성` 실행 여부 |
| Gemini HTTP 429 | 무료 등급 하루 한도 초과. 다음 날 풀림 |
| 글자를 못 읽음 | 사진 다시. 위 "잘 찍는 요령" 참고 |
| 엉뚱하게 이어붙임 | 앱에서 [끊기]로 분리 (앱 완성 후). 원본은 그대로라 안전 |

문제가 생기면 먼저 **`상태확인`**, 그 다음 Apps Script **⏱️ 실행 기록**에서 `poll` 항목의 오류를 본다.
